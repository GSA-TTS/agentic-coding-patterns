## Provenance of this evidence

The classifications and the token table below are **author-reported
evidence from a run the author executed. They have not been independently
verified.** No second person re-ran the probe or checked the gateway side. A
reviewer can trace every classification to the stored result for that sample
(see "Committed run artifacts"), but cannot confirm the run happened as
described without repeating it. A human must also accept, for each of the 12
published models, the narrowing described in "Narrowing accepted by this
publication" below (audio, video, and pdf input become disabled in OpenCode).
Until a human accepts it, treat the narrowing as proposed, not approved.

Scope: this record substantiates **image input only**. It says nothing about
`reasoning`, `audio`, `video`, or `pdf`; none of those is published.

## Step-1 configuration facts

For every one of the 24 models, the configuration OpenCode rendered before any
override had `modalities.input` absent and `reasoning` absent. Nothing in the
rendered configuration pre-set either field, so the unset configuration tested
OpenCode's own default, and the two explicit configurations were the only
overrides. The text control passed for 21 models (all 12 published and the 9
not published) and failed for the 3 unavailable models listed below. The
per-model step-1 facts and text-control results are in the
[per-sample replies file](2026-11-04-opencode-2.0.30-replies.md) and in the
results JSON.

## Decision rule

A model is published as image-capable only if all hold:

1. The text control passed.
2. All 3 samples returned the exact token with the explicit `["text","image"]` configuration.
3. All 3 samples under explicit `["text"]` failed to return the token (negative control).

Samples with `modalities.input` unset are recorded for information (OpenCode
2.0.30 treats unset as text and image). The decision rule counts the explicit
configuration.

`claude_4_7_opus` read 2 of 3 samples with the setting unset (sample 3 was a
refusal) but 3 of 3 with explicit `["text","image"]`, so it qualifies under the
rule.

## Narrowing accepted by this publication (ADR 0006)

A present `inputModalities` array asserts the listed modalities only, and the
OpenCode mapping treats an unlisted modality as disabled. Publishing
`["text","image"]` for the 12 models below therefore **disables `audio`,
`video`, and `pdf` input for them in OpenCode**, even though those were never
probed and may work at the gateway. The data-change review must accept this
narrowing for each of the 12 models, or the field stays absent for it. Models
not listed in the published table keep the field absent (unknown), so OpenCode
2.0.30 keeps its own default for them.

## Reproduction

Run the script (the merged `f0a951f3`; the evidence above was produced
by the earlier `fa813f63`, which differs) inside a
sandbox with the kit's pinned OpenCode 2.0.30, three samples per configuration,
against the live gateway. Tokens are random per run, so a new run produces new
tokens; the classifications and the decision rule are what must reproduce.
Results are expected to vary between runs for the borderline models (the
misreads above); a later change to a published value needs a new evidence file.
