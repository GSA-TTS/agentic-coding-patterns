# prime-agent (acq mixin kit)

Installs [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)
(MIT) inside the sandbox — a terminal AI coding assistant with an embedded
IPython tool. Opt-in mixin; composes with the `usai-provider` kit and the other
GSA kits.

prime-agent is a **TUI, not a web UI**, so this kit publishes **no ports**
(contrast the sibling `paseo` and `openchamber` kits, which each publish a
browser UI port).

## What it does (once the follow-ups land)

- **Install phase** (create-time, root): install the prime-agent CLI + runtime.
- **Startup phase** (every start, agent user):
  1. drop the USAi model catalog into prime-agent's config;
  2. bootstrap prime-agent's IPython kernel.

## Egress allow-list

Deny-by-default. The allow-list in `spec.yaml` is prime-agent's own install and
runtime hosts only:

- `app.primeintellect.ai` — prime-agent's application host
- a `*.r2.dev` bundle CDN host — **GUESSED** placeholder, to be confirmed in #370/#371
- `registry.npmjs.org` — npm packages
- `astral.sh`, `releases.astral.sh` — uv / Python toolchain (Astral)
- `pypi.org`, `files.pythonhosted.org` — Python packages (IPython + kernel deps)
- `github.com`, `objects.githubusercontent.com` — source / release assets

Model-provider egress (`api.gsa.usai.gov`) is **not** here — that is the
`usai-provider` kit's job.

> No leading-`*` host appears in the allow-list: acq's kit translation emits
> allow entries unquoted, and a bare `- *.example.com` is parsed by YAML as an
> alias, breaking the translated spec.

## Backend parity

Written entirely in the neutral hybrid/v1 vocabulary (caps / files / commands /
environment), with no `backend_shortcuts` or `backend_extras`. acq's kit
translation feeds the same spec to whatever backend it has active (sbx, msb).
No published port and no supervisor loop, so no per-backend detached/port
primitives are needed.
